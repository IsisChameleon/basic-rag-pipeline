Step 4

How we implement it — LangGraph + Langfuse

Say: "One graph run per application, checkpointed to Postgres, paused at interrupt() for the officer — human review is a first-class graph state, not a bolt-on."

deterministic node LLM node human gate store / queue managed / external

Determinism kit

Temp 0 + JSON schema + Pydantic validation on every LLM call; prompt versions pinned per run (Langfuse); numeric fields cross-checked against Textract raw values; same input → same flags.

Why the interrupt matters

Human review isn't a separate system — it's a paused graph state. The checkpointer holds state for days at zero compute; the officer's decision resumes the same run, so the audit trail is one continuous thread.

Unhappy paths

Low-confidence field → flagged, not blocked. Callback endpoint down → outbox retries + poll API. Poison message → DLQ + ops alert. Prompt regression → Langfuse eval gate blocks the deploy.

Step 6

Defend it — Well-Architected pillars & alternatives

Say: "Every box maps back to a pillar; and for each big choice, here's the road not taken and why."

PillarIn this design
SecurityPII gated by IdP group at the UI and the API; KMS CMKs everywhere at rest; Bedrock/Textract via PrivateLink (no internet path for PII); per-Deployment IAM via Pod Identity (intake can't invoke models); PII masked in Langfuse traces; audit bucket is WORM.
ReliabilityQueue decouples intake from processing; checkpointer resumes runs after pod loss mid-graph; outbox + retries for callbacks with a poll API as fallback; DLQ + alarms; Aurora multi-AZ.
PerformanceFan-out extraction per document (LangGraph Send); KEDA scales workers on queue depth; the sync 202 path touches no AI so intake latency is milliseconds.
CostWorkers scale to zero off-hours; Textract-first keeps LLM tokens for normalization only; Aurora Serverless scales with load; Langfuse spans give per-application LLM cost attribution.
Operational excellenceOne trace per application end-to-end (OTEL); prompts versioned + eval-gated in Langfuse, deployable without a code release; GitOps deploys on the existing platform; runbook = replay from checkpoint.
SustainabilityScale-to-zero workers, serverless datastores, right-sized managed inference — no idle GPU fleet.
chosen · 202 + callback

vs. synchronous response

Doc processing takes minutes and includes a human gate — holding an HTTP connection is untenable. Callback pushes status transitions; the GET endpoint covers missed webhooks. Sync would only work if we dropped human review.

chosen · LangGraph on EKS

vs. Step Functions

SFN gives similar orchestration + native waits, and is the right answer without the LangGraph requirement. LangGraph wins here on code-native graphs, interrupt() HITL, checkpoint replay, and first-class Langfuse tracing.

chosen · Textract + LLM

vs. LLM-only extraction

LLMs misread digits and invent totals; Textract is deterministic on numbers but can't map layouts to a canonical schema. Hybrid: Textract owns the values, the LLM owns the mapping, validation cross-checks the two.

chosen · rules scorecard

vs. ML / LLM scoring

Regulated credit decisions need reproducible reason codes. A versioned scorecard delivers that today; an ML model can later sit behind the same interface as champion/challenger — the graph doesn't change.

chosen · existing EKS

vs. Bedrock AgentCore

AgentCore would remove the worker infrastructure, but the bank already operates an EKS platform with ingress, IdP, GitOps and on-call — the marginal cost of two Deployments is near zero, and Langfuse self-hosting wants a cluster anyway.

"The system is an evidence factory, not a decision maker: deterministic rules produce the score, LLMs only classify, normalize and draft a policy-grounded memo — and every application pauses at a checkpoint until a licensed credit officer decides. The core platform hears back in milliseconds with a 202, and again with a signed callback at every status change."
